# ШагРитм

Мобильное приложение-шагомер на Expo и React Native.

## Автообновления у пользователей через EAS Update

В проект добавлен `expo-updates`. Release APK, собранный после этой настройки, проверяет обновления при запуске, при возврате приложения на экран и дальше каждые 15 минут, пока приложение работает. Если на сервере есть новая совместимая JS/assets-версия, приложение скачает ее и перезапустится автоматически.

Важно: телефоны, где уже установлен старый APK без `expo-updates`, не могут получить OTA-обновление сами. Им нужно один раз установить новую APK-сборку с включенными обновлениями. После этого изменения в React Native-коде, стилях и assets можно доставлять через OTA.

Первичная настройка EAS-проекта:

```powershell
npx eas-cli login
npm run updates:configure
```

Команда `updates:configure` должна добавить в `app.json` поле `expo.updates.url` вида `https://u.expo.dev/<project-id>`. Android-сборка читает этот URL из `app.json` и включает OTA только когда URL задан.

Production-сборка и публикация обновлений теперь дополнительно проверяют этот URL. Если он не настроен, команды остановятся, чтобы случайно не выдать пользователям APK без связи с сервером обновлений.

Соберите APK, которую пользователи должны установить один раз:

```powershell
npm run build:android:production
```

После установки этой APK пользователями обычные изменения интерфейса и логики публикуются так:

```powershell
npm run update:production -- --message "Описание изменения"
```

Новая версия придет пользователям при следующем запуске приложения или когда приложение вернется из фона. Если менялись native-файлы Android, permissions, Gradle, Expo SDK, нативные зависимости или `version`/`runtimeVersion`, нужно собрать и установить новый APK, а не только отправлять OTA.

## Автообновление приложения на телефонах от компьютера

Для разработки телефоны можно подключить к этому компьютеру как к локальному серверу. В этом режиме приложение на каждом подключенном телефоне берет код с Metro-сервера на компьютере, а изменения в `.ts` и `.tsx` файлах появляются на телефонах автоматически через Fast Refresh.

Первый раз установите debug-сборку на нужный телефон:

```powershell
npm run phone:install
```

После этого подключите один или несколько телефонов по USB и для ежедневной разработки запускайте:

```powershell
npm run phone:live
```

Что должно быть готово на каждом телефоне:

- телефон подключен к компьютеру по USB;
- на телефоне включен Developer mode / Режим разработчика;
- включен USB debugging / Отладка по USB;
- на телефоне подтвержден RSA-запрос от этого компьютера;
- на компьютере доступны Android SDK Platform Tools с `adb.exe`;
- для установки или пересборки debug APK нужны JDK и Android SDK.

Держите окно `npm run phone:live` открытым. Команда сама найдет все подключенные Android-телефоны, подключит каждый к Metro-серверу и откроет приложение. Когда вы меняете файлы интерфейса или логики React Native, все подключенные телефоны обновляют экран автоматически.

Если менялись native-файлы Android, например `android/app/src/main/java/...`, `AndroidManifest.xml`, зависимости или `app.json` permissions, нужен новый APK:

```powershell
npm run phone:rebuild
```

Обычный release APK из `dist/` не подключается к компьютеру как к серверу и не получает локальные изменения автоматически. Для удаленных пользователей используйте EAS Update из раздела выше.

## APK для телефона

Готовый установочный файл Android:

```text
C:\Users\user\repositories\public\шагомер\dist\pedometer-android.apk
```

Скопируйте этот APK на Android-телефон и откройте его на телефоне. При установке Android может попросить разрешить установку из неизвестного источника для приложения, через которое вы открываете APK.

После первого запуска выдайте разрешения:

- Physical activity / Физическая активность - нужно для подсчета шагов.
- Notifications / Уведомления - нужно на Android 13+, чтобы работал постоянный фоновый сервис шагомера.

## Что важно для реального подсчета

На Android приложение использует нативный `TYPE_STEP_COUNTER` датчик и foreground service. Это значит, что счетчик продолжает работать в фоне, пока Android не остановит приложение вручную и пока активен сервис шагомера.

Чтобы счетчик работал стабильнее:

- не закрывайте приложение принудительно из настроек Android;
- не отключайте уведомление шагомера;
- после перезагрузки телефона откройте приложение один раз;
- при необходимости отключите жесткую экономию батареи для приложения.

## Оценка калорий по фото

Слайд `Еда` принимает загруженное фото до 16 МБ или снимок с камеры телефона. После отправки приложение передает само фото в backend-прокси, а backend отправляет это фото в Gemini AI и возвращает готовую оценку калорий клиенту.

- Распознавание еды и расчет калорий делает только Gemini AI через backend.
- Локальный справочник не подставляет резервную оценку, чтобы приложение не показывало ошибочные блюда и калории.
- Если backend Gemini или ключ Gemini не настроены, зона `Оценка порции` не заполняется.
- Расчет калорий примерный: по одному фото нельзя точно измерить вес и состав блюда.

Gemini API-ключ хранится только на backend:

```powershell
$env:GEMINI_API_KEY="ваш_gemini_api_ключ"
npm run backend:gemini
```

Также backend автоматически читает файл `gemini.env` из корня проекта:

```text
GEMINI_API_KEY=ваш_gemini_api_ключ
GEMINI_FOOD_MODEL=gemini-2.0-flash
GEMINI_BACKEND_PORT=18000
```

По умолчанию backend слушает `http://localhost:18000/food-calorie-estimate` и использует модель `gemini-2.0-flash`. Модель и порт можно заменить через `gemini.env` или переменные окружения:

```powershell
$env:GEMINI_FOOD_MODEL="gemini-2.0-flash"
$env:GEMINI_BACKEND_PORT="18000"
```

Для web-preview клиент по умолчанию ходит на `http://localhost:18000/food-calorie-estimate`. Для Android-телефона укажите адрес backend на компьютере или сервере перед сборкой:

```powershell
$env:EXPO_PUBLIC_FOOD_CALORIE_BACKEND_URL="http://192.168.0.102:18000/food-calorie-estimate"
npm run phone:rebuild
```

Не встраивайте `GEMINI_API_KEY` в `EXPO_PUBLIC_*`: такие переменные попадают в клиентскую сборку.

## Где открыть

- Web-preview интерфейса: http://localhost:8082

Web-preview нужен только для просмотра интерфейса в браузере. В браузере нет датчика шагов, поэтому реальные шаги считаются только в Android APK.

## Запуск

```powershell
npm install
npm start
```

Для просмотра интерфейса в браузере:

```powershell
npm run web
```

## Важно

В проекте есть нативная папка `android/`, потому что для полноценного Android-шагомера добавлен собственный модуль и foreground service. Это не Expo Go-приложение для реального использования, а нативный APK.
